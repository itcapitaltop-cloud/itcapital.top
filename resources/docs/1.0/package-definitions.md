<a name="purpose"></a>
## Назначение

Настройки пакетов позволяют администратору управлять тарифами ITC-пакетов без изменения кода. Для каждого тарифа хранится конфигурация с названием, системной категорией поведения, процентом доходности, минимальной суммой старта, сроком работы, изображением карточки и статусом доступности.

Новые пакеты используют актуальную настройку на момент создания. Уже созданные пакеты сохраняют свои экономические параметры в записи пакета и не пересчитываются при изменении или архивации настройки. Это работает как старые тарифы у операторов связи: покупка новых пакетов по тарифу может быть закрыта, но старые пакеты продолжают работать.

<a name="admin-fields"></a>
## Что настраивает администратор

Раздел админки: `Настройки пакетов`.

| Поле | Для чего используется |
|------|------------------------|
| `Slug` | Автоматически генерируется из названия пакета, например `business-start`; нужен как стабильный технический идентификатор тарифа |
| `Системная категория` | Определяет поведение пакета в коде: обычный, подарочный или staking |
| `Название` | Показывается на карточках пакетов вместо системного названия типа |
| `Процент прибыли по умолчанию` | Попадает в новые пакеты как `month_profit_percent` |
| `Минимальная сумма старта` | Используется в проверках покупки и промокодов |
| `Срок работы, месяцев` | Используется для расчета `duration_months` и `work_to` |
| `Изображение карточки` | Загружается на публичный диск и используется в пользовательских карточках |
| `Доступен в ЛК` | Разрешает покупку тарифа пользователем из личного кабинета; если выключено, тариф доступен только для покупки администратором |
| `Порядок сортировки` | Определяет порядок отображения записей в админке |

Администратор не вводит `slug` вручную. При сохранении система строит его из названия и добавляет числовой суффикс при совпадении, например `business-start-2`.

Категорию `archive` нельзя выбрать для настройки пакета. В одной системной категории может быть несколько тарифов с разными `slug`, например несколько обычных пакетов с категорией `standard`.

### Статусы тарифа

| Статус | Что означает |
|--------|--------------|
| `Доступен в ЛК` | Пользователь может купить тариф сам, администратор тоже может купить его вручную |
| `Только в админке` | Пользователь не видит и не покупает тариф в ЛК, но администратор может купить его пользователю вручную |
| `Архив` | Тариф нельзя купить нигде, но уже купленные пакеты продолжают работать |

Архивные тарифы остаются видимыми в списке настроек пакетов, чтобы их можно было найти, посмотреть, отредактировать и восстановить. Для архивных тарифов доступна кнопка `Восстановить`; после восстановления тариф снова становится `Доступен в ЛК`.

<a name="usage"></a>
## Как используются настройки

При создании обычного пакета в личном кабинете система получает тариф со статусом `Доступен в ЛК` и системной категорией `standard`, затем записывает в новый пакет:

| Значение | Источник |
|----------|----------|
| `package_definition_id` | ID выбранной настройки тарифа |
| `month_profit_percent` | `default_profit_percent` настройки |
| `duration_months` | `duration_months` настройки |
| `work_to` | текущая дата плюс срок работы из настройки |

При создании пакета администратором через карточку пользователя админ выбирает конкретный тариф по названию и `slug`. В этом списке доступны тарифы со статусами `Доступен в ЛК` и `Только в админке`; архивные тарифы не показываются. Если текущий админский сценарий разрешает ручной процент или срок, в пакет сохраняются итоговые значения, но связь с тарифом все равно фиксируется через `package_definition_id`.

Для стейкинга используется настройка системной категории `staking`. Стейкинг сохраняет свои отдельные бизнес-правила, но новый staking-пакет получает ID настройки, срок и процент доходности из конфигурации, если настройка доступна для соответствующего сценария создания.

<a name="rules"></a>
## Правила и ограничения

- Для самостоятельной покупки в ЛК нужна настройка со статусом `Доступен в ЛК`.
- Для покупки администратором нужна неархивная настройка: `Доступен в ЛК` или `Только в админке`.
- Если подходящая настройка не найдена, создание пакета останавливается до записи финансовых данных.
- Денежные и токеновые значения хранятся как decimal-строки, без float-расчетов.
- Изменение настройки влияет только на будущие пакеты.
- Уже созданные пакеты сохраняют старые `month_profit_percent`, `duration_months` и `work_to`.
- Архивная настройка не должна использоваться для новых операций, но старые пакеты продолжают ссылаться на нее и отображать ее название/изображение.

<a name="promo-codes"></a>
## Промокоды

Порог минимальной суммы для промокодов берется из настройки пакета. Для стандартного пакета это `min_start_amount` тарифа категории `standard`, доступного в ЛК.

При генерации промокода сниженная минимальная сумма должна быть ниже стандартного минимума из настройки. Например, если `min_start_amount` равен `300.00000000`, промокод с порогом `299.00000000` допустим, а порог `300.00000000` отклоняется.

<a name="cards"></a>
## Карточки пакетов

Пользовательские карточки пакетов могут показывать данные из связанной настройки:

| Элемент карточки | Источник |
|------------------|----------|
| Название | `packageDefinition.name` или системное название типа как резервный вариант |
| Изображение | `packageDefinition.card_image_path` или стандартное изображение как резервный вариант |

Резервный вариант нужен для старых пакетов, у которых нет `package_definition_id`, и для случаев, когда связанная настройка недоступна для отображения.

<a name="activity-log"></a>
## Журнал изменений

На странице конкретной настройки пакета есть блок `Журнал`. Он показывает административные изменения тарифа.

Колонки журнала:

| Колонка | Содержимое |
|---------|------------|
| `Событие` | Название действия, например создание, изменение, архивация или восстановление тарифа |
| `Логин администратора` | Логин администратора, который выполнил действие |
| `Старые значения` | Значения полей до изменения |
| `Новые значения` | Значения полей после изменения |
| `Дата` | Дата и время события |

Журнал использует существующую таблицу `activity_log` и модель `BusinessActivity`. Записи пагинируются по 15 строк. Над таблицей есть поиск по названию события.
