<a name="purpose"></a>
## Назначение

Поддержание ранга гарантирует, что высокий ранг сохраняется только при сохранении активности структуры. Каждый месяц система проверяет оборот по линиям за расчётный период и при невыполнении требований понижает ранг на один шаг.

В отличие от ручного ранга (см. [Ручной ранг пользователя](/{{route}}/{{version}}/manual-rank)), поддержание работает автоматически по расписанию и затрагивает только пользователей с естественным рангом.

<a name="terms"></a>
## Основные понятия

- Расчётный месяц (окно): предыдущий полный календарный месяц, за который оценивается оборот.
- Месячный оборот линии: оборот, сгенерированный внутри окна, а не накопленный за всё время.
- Порог поддержания: набор требований по линиям ранга `N-2`, который нужно выполнить, чтобы сохранить ранг `N`.
- Накопленный оборот: суммарный оборот по линиям за всё время, который используется для повышения ранга и при понижении не обнуляется.
- Базлайн понижения (`users.rank_demoted_at`): дата последнего понижения; пока он установлен, к повышению засчитывается только оборот, сгенерированный после этой даты.

<a name="maintenance"></a>
## Поддержание ранга

Чтобы сохранить текущий ранг `N`, за расчётный месяц пользователь должен выполнить требования по линиям ранга `N-2` (входящий оборот рефералов).

- Проверяется только **месячный** оборот по линиям внутри окна, накопленный оборот за всё время в проверке не участвует.
- Личный депозит в ежемесячной проверке не учитывается — это постоянная величина, а не месячный поток. Требования по личному депозиту относятся только к повышению.
- Если по всем требуемым линиям месячный оборот не ниже требуемого — ранг сохраняется.

<a name="demotion"></a>
## Постепенное понижение

Если хотя бы по одной требуемой линии месячный оборот ниже требуемого, ранг понижается ровно на один шаг (`N → N-1`):

- понижение не пересчитывает ранг до «естественного» — это всегда один шаг за один проваленный месяц;
- в следующем месяце порог поддержания пересчитывается от нового ранга (`(N-1)-2`);
- накопленный оборот по линиям сохраняется и не обнуляется;
- при каждом понижении в `users.rank_demoted_at` записывается граница расчётного окна (начало текущего месяца) — это базлайн для [возврата ранга](#regain);
- понижение идемпотентно в пределах окна: в `users.rank_demotion_period_end` фиксируется уже обработанное окно, и повторный запуск команды за тот же месяц (вручную или из-за сбоя расписания) повторного понижения не выполняет — один проваленный месяц наказывается ровно один раз, даже если ранг уже был возвращён;
- `users.max_rank_awarded` при понижении не меняется (см. [бонус](#bonus));
- понижению подлежат только ранги `≥ 3`: для `N ≤ 2` порог `N-2 ≤ 0`, требований по линиям нет;
- ранг не опускается ниже 1;
- пользователи с включённым ручным рангом (`overridden_rank = true`) ежемесячным заданием не понижаются — ими управляет администратор.

При понижении пишется событие журнала `partner_rank_decreased` (с `old_rank`, `new_rank`, периодом) и отправляется уведомление пользователю.

<a name="regain"></a>
## Возврат ранга после понижения

Чтобы вернуть потерянный ранг, требования этого ранга нужно выполнить заново — **за счёт оборота, сгенерированного после понижения**:

- пока `rank_demoted_at` установлен, естественный расчёт ранга учитывает по линиям только оборот с этой даты; старый (накопленный до понижения) оборот к повышению не засчитывается и не может автоматически вернуть ранг;
- требование по личному депозиту проверяется как обычно (это постоянная величина, а не месячный поток);
- при каждом следующем понижении базлайн сдвигается на новую дату понижения;
- когда пользователь снова достигает своего пикового ранга (`max_rank_awarded`) или превышает его, базлайн сбрасывается (`rank_demoted_at = NULL`) и оборот снова считается за всё время;
- прогресс-бары в кабинете партнёра для понижённого пользователя также показывают только оборот, сгенерированный после понижения;
- на пользователей с ручным рангом (`overridden_rank = true`) базлайн не влияет — у них своя базовая логика от `overridden_rank_from`.

<a name="bonus"></a>
## Одноразовый бонус за ранг

Бонус за достижение ранга начисляется один раз за ранг на пользователя:

- бонус платится, только если новый ранг превышает значение `users.max_rank_awarded`;
- после начисления `max_rank_awarded` поднимается до нового ранга;
- если ранг был потерян и затем снова достигнут (ранг `≤ max_rank_awarded`), ранг повышается, событие `partner_rank_increased` пишется с `bonus_awarded = false`, но **бонус повторно не платится**.

Колонка `users.max_rank_awarded` добавлена миграцией и при установке заполнена текущим рангом каждого пользователя, чтобы уже полученные ранги не приводили к повторной выплате.

<a name="promote-only"></a>
## Реалтайм-пересчёт работает только на повышение

Реалтайм-пересчёт `recalculateAndUpdateRank()` (срабатывает при покупке пакета и действиях администратора) только **повышает** ранг:

- если рассчитанный ранг ниже текущего, понижение не сохраняется (возвращается `false`);
- понижение выполняет исключительно ежемесячное задание поддержания, по одному шагу.

<a name="command"></a>
## Команда и расписание

```bash
# Обслужить всех пользователей за предыдущий календарный месяц
php artisan partner:rank-maintenance

# Только один пользователь
php artisan partner:rank-maintenance --user=123

# Рассчитать понижения без сохранения (только лог)
php artisan partner:rank-maintenance --dry-run
```

Задание зарегистрировано в `routes/console.php` по расписанию `monthlyOn(1, '00:30')` — после ночных начислений профита (`00:00`), с `withoutOverlapping()` и `onOneServer()`. Окно расчёта — предыдущий полный календарный месяц (`now()->subMonthNoOverflow()->startOfMonth()` … `now()->startOfMonth()`).

<a name="example"></a>
## Пример расчёта

Пользователь имеет ранг 5. Порог поддержания — требования по линиям ранга 3, например линия 1: `1000`.

- За расчётный месяц по линии 1 сгенерировано `300` (< `1000`) → ранг понижается до 4.
- В следующем месяце порог — ранг 2, и снова не выполнен → ранг понижается до 3.

Накопленный за всё время оборот по линиям при этом остаётся прежним, но к возврату ранга он не засчитывается: вернуть ранг 5 можно только выполнив его требования оборотом, сгенерированным после понижения (см. [возврат ранга](#regain)). Бонус за уже полученные ранги повторно не начисляется.
