<a name="purpose"></a>
## Назначение

Раньше администратор видел заявки клиента на ввод и вывод только в общих разделах `Ввод` и `Выводы`, где нужно было искать пользователя среди всех остальных. Вкладки `Ввод` и `Вывод` в карточке клиента показывают заявки одного пользователя и позволяют менять их статус, не покидая карточку.

Набор колонок и кнопок совпадает с общими разделами, за исключением колонки «Пользователь» — в карточке клиента она избыточна.

<a name="deposits"></a>
## Вкладка «Ввод»

| Колонка | Что показывает |
|------|------------------------|
| `Дата создания депозита` | Момент создания заявки |
| `Сумма транзакции` | Сумма заявки |
| `Хеш транзакции` | Хеш перевода; для хеша USDT (TRC-20) рядом появляется ссылка на Tronscan |
| `Крипто/ Фиат` | Способ пополнения: `Крипто (USDT)` либо значение хеша для фиата |
| `Статус` | Статус заявки и кнопки управления |

<a name="withdraws"></a>
## Вкладка «Вывод»

| Колонка | Что показывает |
|------|------------------------|
| `Дата заявки на вывод` | Момент создания заявки |
| `Сумма` | Запрошенная сумма |
| `Комиссия` | Комиссия за вывод |
| `К выводу` | `Сумма − Комиссия`; считается через `BigDecimal` без плавающей точки |
| `Адрес` / `Карта` / `Счёт` | Реквизиты. Для фиатных выводов подставляются телефон СБП, банк и ФИО получателя |
| `Крипто/Фиат` | Определяется по формату адреса кошелька: ETH, USDT (TRC-20), BTC либо `Фиат` |
| `Статус` | Статус заявки и кнопки управления |

Над таблицей есть кнопка `Создать заявку на вывод`. Она открывает ту же форму, что и в общем разделе `Выводы`, но без выбора аккаунта: заявка всегда создаётся владельцу открытой карточки.

<a name="actions"></a>
## Кнопки управления заявкой

Набор кнопок зависит от текущего статуса заявки.

| Статус | Доступные действия |
|------|------------------------|
| `На модерации` | `Принять`, `Отклонить`, редактирование суммы заявки |
| `Отклонено` (ввод) | Выпадающий список: вернуть `На модерации` либо перевести в `Исполнено` |
| `Исполнено` (ввод) | Действий нет, показывается только статус |
| Любой статус кроме `На модерации` (вывод) | Модалка `Редактировать заявку`: сумма и новый статус |

Статус заявки не хранится отдельной колонкой — он выводится из пары `accepted_at` / `rejected_at` транзакции:

- оба поля пустые — `На модерации`;
- заполнен `accepted_at` — `Исполнено`;
- заполнен `rejected_at` — `Отклонено`.

<a name="filters"></a>
## Фильтры и пагинация

Над таблицей каждой вкладки есть фильтр по статусу заявки и по периоду создания. Заявки выводятся постранично, по 25 записей.

Фильтр и номер страницы живут в адресной строке, поэтому ссылку на отфильтрованную вкладку можно сохранить или передать. Имена параметров разведены префиксом вкладки, чтобы фильтр одной вкладки не применялся ко второй:

| Вкладка | Параметры |
|------|------------------------|
| `Ввод` | `deposits_status`, `deposits_date_from`, `deposits_date_to`, `deposits_page` |
| `Вывод` | `withdraws_status`, `withdraws_date_from`, `withdraws_date_to`, `withdraws_page` |

Как и остальные вкладки карточки, обе вкладки загружаются отложенно: данные запрашиваются только при первом открытии вкладки, а не при каждом заходе в карточку.

<a name="activity-log"></a>
## Журнал событий

Смена статуса из карточки клиента пишется так же, как из общих разделов:

- бизнес-событие через `laravel activity log` с типами `deposit_approved`, `deposit_rejected`, `withdraw_approved`, `withdraw_rejected` — попадает в фиды `Финансы` и в журнал пользователя внутри карточки;
- запись в админский журнал с прежним и новым значением `accepted_at` / `rejected_at`.

<a name="implementation"></a>
## Где реализовано

| Слой | Файл |
|------|------------------------|
| Вкладки и таблицы | `app/MoonShine/Pages/User/UserDetailPage.php` |
| Выборка заявок клиента | `app/Repositories/UserFinanceRequestRepository.php` |
| Фильтр вкладок | `app/Dto/Finance/FinanceRequestFilterData.php` |
| Форма фильтра | `resources/views/admin/partials/user-finance-filter.blade.php` |
| Действия смены статуса | `app/Http/Controllers/AdminController.php` (`financeAccept`, `financeReject`, `financeModerate`) |
| Логика статусов и журналирование | `app/Traits/Moonshine/CanStatusModifyTrait.php` |
| Роуты | `routes/web.php` — `admin.finance.accept`, `admin.finance.reject`, `admin.finance.moderate` |
| Тесты | `tests/Feature/AdminUserCardFinanceTabsTest.php`, `tests/Feature/AdminUserCardFinanceActionsTest.php` |

Кнопки статуса вызывают роуты `admin.finance.*`, а не методы MoonShine-ресурса: внутри карточки клиента текущий ресурс — `UserResource`, у которого методов `accept` / `reject` / `toModerate` нет, поэтому кнопки из общих разделов там не резолвятся.
