# Promo code generation resolves Privilege and VIP package definitions

**Date:** 2026-05-31 18:32
**Files:** app/Services/Package/PackageDefinitionResolver.php, tests/Feature/PromoCodeTest.php
**Severity:** high

## Problem

Admin promo code generation failed for `vip` and `privilege` with: `Active package definition for [vip] is not configured.` The same issue affected `privilege`.

## Root Cause

Package definitions for commercial tariff variants are stored with unique tariff slugs (`standard`, `privilege`, `vip`), but their system category can remain `standard` for regular ITC packages. `PackageDefinitionResolver::resolve()` searched by `type`, so resolving `vip` or `privilege` required rows whose `type` was exactly `vip` or `privilege`. Seeded rows use `slug=vip` / `slug=privilege` with `type=standard`, therefore the resolver could not find them.

## Solution

Changed `PackageDefinitionResolver::resolve()` to resolve active package definitions by `slug` matching the requested `PackageTypeEnum` value. Added `[FIX:promo-code-package-definition]` logs for missing and successful resolution. Added regression coverage proving promo codes can be generated for active `privilege` and `vip` definitions.

## Prevention

- When package variants are represented by rows in `package_definitions`, use `slug` for a concrete tariff identity and `type` for broad system category.
- Add regression tests for every admin flow that resolves non-standard package variants.
- During review, check that queries do not confuse concrete package slug with category type.
